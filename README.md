[**SEO Expert Agency**](https://seoexpertagency.com) is a data-driven SEO agency marketing site.
Built with Next.js 16 (App Router), React 19, Supabase, and TailwindCSS, it showcases the
agency's services, industries, and case studies, generates local-SEO landing pages, and runs a
full content-management admin portal behind it.

---

## 🌟 Key Features

### Public Experience & SEO Engine
- **Services / Industries / Projects / Locations catalogs**: each a CMS-managed content type with
  its own hero, overview, problems/benefits/deliverables, process, and FAQ sections.
- **SEO Pages**: local-SEO landing pages generated by combining a Service with a Location (e.g.
  "Local SEO in Dubai" at `/dubai/local-seo`), each individually editable with automatic
  cross-linking to sibling pages.
- **SEO Blog**: full CMS blog with categories, tags, and Arabic translation support.
- **High-performance architecture**: Incremental Static Regeneration (ISR) and Server-Side
  Generation (SSG) for sub-second page loads.
- **Automated JSON-LD schema engine**: emits `Service`, `FAQPage`, `BreadcrumbList`, and
  `Organization` schemas dynamically for every public page.
- **Lead capture**: rate-limited, honeypot-protected forms with instant email notifications via
  Resend.

### Admin Portal (`/admin`)
- **Role-based access control**: `super_admin`, `admin`, `editor`, `content_writer`,
  `support_staff`, and a restricted `seo_editor` role, enforced by Next.js middleware
  (`src/proxy.ts`) and PostgreSQL Row Level Security.
- **Generic CMS core**: Services, Industries, Projects, Locations, and SEO Pages all share one
  admin CRUD stack (`src/lib/content-api.ts` + `src/lib/content-resources.ts`) — adding a new
  content type is a schema and a form spec, not a copied route.
- **SEO Blog CMS**: rich-text editor, approval/assignment workflow, live SERP/OpenGraph preview.
- **Static Page SEO**: per-page meta title/description/robots/canonical editor for every static
  route (home, about, contact, etc).
- **Media management**: Supabase Storage-backed picker for WEBP/PNG assets.
- **On-demand cache purging**: admin saves call `revalidatePage()` to sync edits to the live site
  in under 2 seconds.

## 🏗️ Architecture & Technology Stack

```text
Public Visitors  ──► Vercel Edge ──► Next.js 16 (ISR / SSG) ──► Supabase (Anon RLS)
Admin Users      ──► Vercel       ──► Next.js (/admin)       ──► Supabase (Service Role / Auth)
Admin Publish    ──► revalidatePage() ──────────────────────► ISR Edge Cache Purge (<2s)
```

| Layer | Technology | Description |
|---|---|---|
| **Framework** | Next.js 16.2 (App Router & Turbopack) | Modern hybrid SSG / ISR / Server Components |
| **UI Library** | React 19.2 + Lucide Icons | Component-driven UI with fluid micro-interactions |
| **Styling** | TailwindCSS 4 + Vanilla CSS | Responsive design tokens |
| **Database & Auth** | Supabase (PostgreSQL 15) | Relational database, RLS policies, Storage, & Auth |
| **Rate Limiting** | Upstash Redis | Distributed sliding-window rate limiting for lead APIs |
| **Email Service** | Resend API | Transactional lead alerts & admin notifications |
| **Monitoring** | Sentry + Google Analytics 4 | Real-time client/server error tracking & telemetry |

## 🚀 Getting Started

### Prerequisites

- **Node.js**: `20.9.0` or higher — **`22.14.0` recommended** (pinned in `.nvmrc`; run
  `nvm use` to match). Next.js 16 requires `>=20.9.0` and will fail to install on Node 18.
- **pnpm**: `9.15.4` — pinned via `packageManager`, so `corepack enable` selects it
  automatically. `pnpm-lock.yaml` is committed; always install with `--frozen-lockfile` in CI.
- **Supabase Account**: For database and storage setup

### 1. Clone & Install Dependencies

```bash
git clone https://github.com/carwokshop/seoexpertaagency-web.git
cd seoexpertaagency-web
nvm use          # picks up .nvmrc (22.14.0)
corepack enable  # activates pnpm 9.15.4
pnpm install
```

### 2. Configure Environment Variables

Create a `.env.local` file based on `.env.example`:

```bash
cp .env.example .env.local
```

Key required variables:

```env
NEXT_PUBLIC_SUPABASE_URL=https://your-supabase-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-supabase-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-supabase-service-role-key
NEXT_PUBLIC_SITE_URL=http://localhost:3000
REVALIDATION_SECRET=your-32-char-random-secret
RESEND_API_KEY=re_your_resend_api_key
ADMIN_EMAIL=admin@seoexpertagency.com
```

### 3. Run Development Server

```bash
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser to view the application.

### 4. Database Migrations

Schema lives in `supabase/migrations/` as forward-only, numbered SQL files.
Migrations are applied through `scripts/db.sh`, which requires an explicit
target so production is never hit by accident:

```bash
cp .env.migrate.example .env.migrate   # fill in staging + production connection strings
pnpm db:new add_something              # scaffold a migration
pnpm db:staging:push                   # rehearse against the staging project
pnpm db:prod:push                      # apply to production (typed confirmation)
```

Every schema change goes to staging first. Full setup and workflow:
[DEPLOYMENT.md § 1.8](DEPLOYMENT.md).

## 🚢 Deployment

For full details on deploying to Vercel and configuring Supabase webhooks, consult the
[Production Deployment Guide](DEPLOYMENT.md).

Quick Vercel deployment checklist:
1. Import the repo — the app lives at the repo root, no custom Root Directory needed.
2. Add environment variables from `.env.example`.
3. Set build command: `pnpm build`.
4. Deploy!
